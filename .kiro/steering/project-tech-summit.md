# Project Steering — tech_summit (Project Level — Tier 3)

> Scoped to this repository only. Activated when working on this project's CDK code,
> Lambda handlers, or tests. Inherits org + team steering and adds project-specific detail.

## What this project is

A CDK Python app with two stacks, selected by the `deployment_type` CDK context variable:

- **`cdk ... -c deployment_type=app` → `TechSummitStack`** (the application): a URL
  shortener — an API Gateway REST API (guarded by a Lambda token authorizer that checks
  an auto-generated Secrets Manager API key) in front of a Lambda, backed by a DynamoDB
  table. Handlers live in `lambda/url_shortener/` and `lambda/authorizer/`.
- **`cdk ...` (no `deployment_type`) → `PipelineStack`** (the CI pipeline): a classic
  CodePipeline — Source (GitHub via CodeConnections) → CodeValidation (quality + security
  agents in parallel) → Deploy. Each gate is a `KiroCliStep` running a Kiro CLI agent
  headless.

## Project rules

- Entry point is `app.py`; stacks live in `tech_summit/`. Lambda code lives in `lambda/`.
- **Lambda handlers use the API Gateway REST proxy event shape** (`event["httpMethod"]`,
  `event["path"]`), NOT the Function URL shape (`requestContext.http`). Keep tests in the
  same shape.
- Never hard-code secrets. The app's API key is auto-generated by Secrets Manager; the
  Kiro CLI key is injected into CodeBuild as a `SECRETS_MANAGER` env var, never inlined.
- Keep IAM grants scoped (`grant_read_write_data`, `grant_read`); no wildcards in
  first-party code.
- cdk-nag (`AwsSolutionsChecks`) is applied to the **application stack only**, not the
  pipeline stack (whose L2 constructs generate expected wildcard policies).

## Agents, gates & the `CI` rule

- Quality/security/deploy agents run their tools themselves; the gate agents are
  read-only, the deploy agent may `cdk deploy` but never `cdk destroy`.
- **Virtualenv rule:** locally (`CI` unset) always use a `.venv`; in CI (`CI` set by the
  pipeline) never use one — CodeBuild is ephemeral.
- **Bandit must run under Python < 3.14** (it crashes on 3.14's removed `ast.Num`). CI
  uses Python 3.11, so it is fine there.
- **gitleaks** needs `.git` present; the pipeline Source uses `code_build_clone_output=True`
  so history is scannable, and `CI=true` makes the agent run `gitleaks detect`.

## Build / test commands

- Synthesize app: `cdk synth -c deployment_type=app`
- Synthesize pipeline: `cdk synth`
- Lint: `pylint app.py tech_summit`  ·  Tests + coverage: `coverage run --branch -m pytest && coverage report`
- Coverage omits the pipeline IaC (`pipeline_stack.py`, `kiro_cli_step*.py`, `source_config.py`)
  and `app.py`; it measures the Lambda handlers and the app stack.
